Searching: grep 🔎

grep ">" sequences.fasta        # only header lines
grep -c ">" sequences.fasta     # COUNT them = number of sequences
grep -i "brca" sequences.fasta  # ignore upper/lower case
grep -v ">" sequences.fasta     # everything EXCEPT headers

-c = count · -i = ignore case · -v = invert

15–20 min. grep -c ">" is the classic “how many sequences do I have” one-liner. Make sure everyone sees it work. Always put the pattern in quotes — > without quotes means “write to a file” (next slides!).

Pipes: | 🔗

The output of one command becomes the input of the next.

grep -v ">" sequences.fasta | wc -l    # how many sequence lines?
grep ">" sequences.fasta | head -n 3   # first 3 headers

Small tools, combined. That is the whole idea of the terminal.

20–25 min. Analogy: a pipeline in the lab — each step passes the sample to the next step.

More small tools: cut sort uniq ✂️

cut -d " " -f 2,3 file   # split lines at spaces, keep fields 2 and 3
sort file                # sort lines alphabetically   (-n = numbers, -r = reverse)
uniq -c                  # count repeated neighbouring lines

Which species are in my file, and how many sequences each?

grep ">" sequences.fasta | cut -d " " -f 2,3 | sort | uniq -c | sort -nr
      4 Homo sapiens
      3 Mus musculus
      2 Gallus gallus
      2 Danio rerio
      1 Rattus norvegicus

Build the pipe step by step live: run after every | and show what changed. Why sort before uniq? uniq only merges NEIGHBOURING identical lines. Try without sort — ask what happens.

Saving results: > 💾

grep ">" sequences.fasta > headers.txt     # write to a file
grep ">" sequences.fasta >> headers.txt    # ADD to a file

Warning

> overwrites the file without asking. >> adds at the end.

25–28 min. Ask: after both commands, how many lines are in headers.txt? (24)

Find & replace: sed 🔁

DNA → RNA: every T becomes U

sed 's/T/U/g' sequences.fasta
#     │ │ │ └─ g = global: every match in the line, not only the first
#     │ │ └─── replace with
#     │ └───── find
#     └─────── s = substitute

Look at the headers… 🤔

>seq3 Homo sapiens UP53 partial
sed '/^>/!s/T/U/g' sequences.fasta   # only on lines NOT starting with >

28–32 min. The “UP53” bug is the point: tools do exactly what you say, not what you mean. Always look at your output. ^ = start of line (a regular expression) — just a taste, no deep dive. sed does NOT change the file — it prints the result. Save with >.

Scripts: save your commands 📜

A script = commands in a file, run with one word. Your analysis becomes repeatable.

#!/bin/bash
# count_seqs.sh — how many sequences are in a FASTA file?

file=$1                          # $1 = the first thing after the script name
n=$(grep -c ">" "$file")         # $( ) = save the output of a command
echo "$file contains $n sequences"
bash scripts/count_seqs.sh data/sequences.fasta
data/sequences.fasta contains 12 sequences

52–57 min. Line 1 = shebang: which program should run this file. No spaces around = in variables! file = $1 is an error — everyone makes it once. Quotes around “$file” protect against file names with spaces (remember Bandit?).

Making it executable 🔑

ls -l scripts/count_seqs.sh
-rw-r--r--  1 anna  staff  180 Oct  7 10:12 count_seqs.sh

r = read · w = write · x = execute — for owner · group · others

chmod +x scripts/count_seqs.sh      # add x = allowed to run
./scripts/count_seqs.sh data/sequences.fasta

Loop — the same thing for every file:

for f in data/*; do
  bash scripts/count_seqs.sh "$f"
done

57–60 min. Windows / Git Bash: permissions behave differently — bash script.sh always works, that’s enough. The loop is where the terminal beats clicking: 3 files or 3000 files, same line.

Command What it does

cmd1 \| cmd2 Pipe: output → input

> file >> file Save · append

Homework 🏠

  1. Add .gitignore to your repo, commit and push
  2. SSH key for GitHub — no more typing passwords/tokens:
ssh-keygen -t ed25519 -C "your_email@example.com"   # press Enter 3×
cat ~/.ssh/id_ed25519.pub     # the PUBLIC key → copy it

GitHub → Settings → SSH and GPG keys → New SSH key → paste

ssh -T git@github.com         # "Hi <name>! You've successfully authenticated"

🔒 id_ed25519.pub = public, share freely · id_ed25519 = private, never share

  1. Optional: Bandit levels up to 5 🏴‍☠️

Key pair analogy: public key = a padlock you give to servers; private key = the only key that opens it. To switch an existing repo to SSH: git remote set-url origin git@github.com:<user>/<repo>.git (check with git remote -v). Copying files to/from a server (for the curious): scp -P 2220 bandit0@bandit.labs.overthewire.org:readme . — note capital -P in scp!
